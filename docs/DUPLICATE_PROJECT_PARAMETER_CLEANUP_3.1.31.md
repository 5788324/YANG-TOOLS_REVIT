# YangTools 3.1.31 重复项目参数清理

## 本轮目标

1. 支持全选、全不选、反选。
2. 支持先用不超过 10 个来源参数做小范围测试。
3. 解决扫描很快、删除阶段明显卡顿的问题。
4. 保留原参数合并、单次遍历、原始值复制和级联删除保护。

## 选择工具

列表上方新增：

- `全选可处理项`：选中全部兼容重复组。
- `全不选`：清空全部选择，便于手工选择少量行。
- `反选`：只反转兼容组；不兼容组始终不参与处理。
- `测试：最多 10 个来源参数`：自动选择若干完整重复组，使来源参数总数不超过 10。

每一行代表一个重复参数组。一个组可能有多个来源参数，因此“前 10 行”不等于“10 个参数”。本轮采用来源参数总数限制，确认框和工具栏会同时显示：

```text
已选 N 组 / M 个来源参数
```

## 删除为什么卡

3.1.30 的删除结构是：

```text
每个来源参数
→ Start SubTransaction
→ Document.Delete(parameterId)
→ 检查级联 ID
→ Commit / RollBack
```

如果存在 600–2000 个来源参数，就会重复执行同等数量的 Revit 依赖分析和子事务提交。扫描 55ms 并不能代表删除同样快，瓶颈在 Revit 数据库写操作。

## 3.1.31 自适应批量删除

默认每批 25 个来源参数：

```text
25 个参数 ID
→ 一次 Document.Delete(ICollection<ElementId>)
→ 比较返回 ID 集合
```

只有满足下面条件才提交：

```text
返回的删除 ID == 本批请求的参数 ID
```

如果出现以下任一情况：

- 返回额外级联对象；
- 某个请求参数未出现在返回结果；
- Revit 抛出异常；

则当前批次立即回滚，然后自动二分：

```text
25 → 12 + 13 → 6 + 6 ... → 单个参数
```

正常的一半仍可一次批量提交，只有异常分支继续拆分。拆到单个参数后，记录具体级联对象或异常原因并保留该参数。

## 模拟结果

`tools/Test-ParameterCleanupPipeline.py` 的纯逻辑模拟：

| 场景 | 旧逐项调用 | 新调用次数 | 结果 |
|---|---:|---:|---|
| 10 个全部安全 | 10 | 1 | 全部删除 |
| 606 个全部安全 | 606 | 25 | 全部删除 |
| 606 个，1 个级联 | 606 | 35 | 只拒绝该 1 个 |
| 606 个，4 个级联 | 606 | 约几十次 | 分别隔离 4 个 |

模拟不代表 Revit 实际秒数，但可以验证调用数量和隔离逻辑。

## 不变的核心原则

### 不删除重建

继续保留一个现有 `ParameterElement`，合并绑定和值，再删除允许删除的来源参数。

### 按元素单次遍历

实例元素和类型元素各一次 `FilteredElementCollector`，通过参数 ID 字典匹配，不按参数组重复扫描模型。

### 不用显示字符串回填

- Double：`AsDouble()` → `Set(double)`
- Integer：`AsInteger()` → `Set(int)`
- String：`AsString()` → `Set(string)`
- ElementId：`AsElementId()` → `Set(ElementId)`

`AsValueString()` 仅用于报告显示。

## 实机测试顺序

1. 使用 RVT 副本。
2. 扫描。
3. 点击 `测试：最多 10 个来源参数`。
4. 点击 `快速处理：合并并清理`。
5. 检查自动复核报告。
6. 保存删除日志中的性能统计。
7. 使用 Revit 撤销，确认参数恢复。
8. 10 个来源参数测试通过后，再处理全部。
