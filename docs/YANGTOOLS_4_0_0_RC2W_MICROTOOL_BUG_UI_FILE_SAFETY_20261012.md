## 确认并修复的旧代码风险

1. 收藏包删除原来仅检查仓库内存在 `microtool.package.json`，没有验证清单声明的 `MainDll` 是否与用户选择的主 DLL 相同，允许错误路径整目录删除。现在要求：**默认收藏仓库直属一级目录**、确实存在有效包清单、主 DLL 为包内正规路径并存在、清单主 DLL 与选中 DLL 一致，所有涉及路径不得为 junction/symlink/reparse-point。失败拒绝删除。
2. 同名收藏更新原来只检查用户选择覆盖，可能将普通文件夹移动到备份、之后删除。现在覆盖前必须校验目标是**现存有效受管理收藏包**，无法确认不修改原目录。
3. 收藏/运行影子副本原来递归枚举目录未处理 NTFS 目录链接，可能循环、穿越目录或把意外文件复制进缓存。现在复制专用递归枚举器对任意目录/文件重解析点显式拒绝，普通 UI 扫描跳过重解析目录并记录诊断。
4. “清理运行缓存”原来删除缓存根下所有过期子目录，即使不是工具创建的目录。现在仅清理合法正整数 PID 命名、非本会话、非运行进程且满足年龄条件的目录，目录链接拒绝删除。
5. 更新项目仓库 JSON 原来先删正式文件再重命名临时文件，崩溃可能丢配置；现在用同目录 `File.Replace` 更新旧文件，新建时采用 `File.Move`。
6. 收藏 UI 原来 `catch(IOException)` 会把权限不足或磁盘故障误判为“同名冲突”，诱导覆盖。改为 `MicroToolPackageConflictException` 仅处理真正同名冲突；其他异常显示错误。
7. UI 帮助增加临时 DLL **在 Revit 进程内执行，无沙箱** 的明确警告，防止把插件箱误当安全执行器。

## 设计边界

- 动态加载 DLL 不等于进程沙箱；程序集通常在当前 AppDomain 不能按一次运行卸载，影子副本只是避免原 DLL 长期锁定。未尝试改变 DLL 解析架构或允许执行不可信代码。
- 严格复制拒绝 symlink/junction 路径，可能导致个别旧收藏项目无法复制：这是有意的安全降级，不会静默跳过依赖。
- 仅禁止不受管理目录整包删除；普通“删除文件”仍为显式不可撤销文件操作，未改成回收站或跨文件原子删除。
- C#/.NET SDK、Windows 文件系统、Revit 2021–2027 GUI、DLL 动态加载、真实依赖解析、Undo 全部 **NOT_TESTED**。专项测试为源码合同与 Python 路径模拟，**不等于执行 C# 或 DLL**。
- 不修改旧 MCP 27 wire、钢筋、Ribbon、安装器、csproj；不新增 MCP route，不推 Git，不使用 Mimo，不要求用户人工验收。

## 后续风险

- 第三方 DLL 可执行任意进程内代码，无法用本插件提供权限隔离。
- 复制程序集加载、相同 AssemblyName 不同版本、跨版本 Revit API 等仍需 Windows/Revit 运行验证。
- 普通“删除文件”及同名配置文件的归属关系、跨进程文件锁，仍需后续运行验收。
- 其他项目管理高耦合 UI 留在下一批；任何 static PASS 不得升级 4.0.0 RELEASE GO。
