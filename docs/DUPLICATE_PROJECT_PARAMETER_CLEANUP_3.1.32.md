# YangTools 3.1.32 重复项目参数清理

## 本轮补充目标

清理完成不能只看“删除了多少参数”，必须同时证明：

1. 本轮已完整清理的同名参数组最终只剩一个 `ParameterElement`；
2. 清理前元素上已有的参数值没有丢失。

## 清理前快照

点击“快速处理：合并并清理”或“仅删除”后，正式写模型前会建立快照：

- 只处理当前选中的兼容参数组；
- 实例元素和元素类型各遍历一次；
- 按参数 ID 匹配，不使用 `LookupParameter(name)`；
- 每个元素、每个同名参数组保存所有不同的非空内部值；
- Double、Integer、String、ElementId 保存原始内部值，不使用 `AsValueString()`。

如果同一元素的多个重复参数值本来不同，快照会同时保留这些不同值。这样即使用户打开“冲突时仍删除”，后续复核也能发现其中某个值是否真的丢失。

## 提交前复核

合并和值复制、自适应批量删除完成后，程序仍处于外层 `TransactionGroup` 中，此时执行第二次只读扫描。

### 参数值完整性

对快照中的每个不同非空值检查：

```text
清理前存在的内部值
→ 清理后同一元素上的同名项目参数集合中仍能找到
```

以下任一情况判定失败：

- 原值不再存在；
- 元素意外不存在；
- 快照阶段读取不完整；
- 复核阶段读取失败；
- 清理后找不到任何同名参数。

失败时不调用 `TransactionGroup.Assimilate()`，整个快速处理或仅删除操作自动回滚。

### 参数唯一性

对每个选中重复组统计：

- 清理前参数数量；
- 成功删除的来源数量；
- 受保护或失败的来源数量；
- 清理后同名项目参数数量。

如果所有来源参数都报告删除成功，那么清理后必须精确剩余一个项目参数。出现 0 个或仍有 2 个以上时判定实现异常并回滚。

因共享参数、明细表/过滤器引用、全局参数、参数值冲突或级联删除对象而保留来源参数时，不强制回滚，但明确报告该组仍未完全清理。

## 性能

本轮没有恢复逐参数扫描。快照与复核均采用按元素单次遍历。对于当前约 2000+ 构件的项目，新增的是两次只读遍历，主要耗时仍然是 Revit 的绑定写入和 `Document.Delete()`。

删除继续使用 3.1.31 的自适应批量策略：默认 25 个来源参数一批，异常批次二分定位。

## 首次验收

1. 使用 RVT 副本。
2. 扫描后点击“测试：最多 10 个来源参数”。
3. 执行快速处理。
4. 运行输出必须出现：
   - `元素参数值：通过`
   - `已完成删除组唯一性：通过`
5. 打开 08、09 CSV，缺失值应为 0。
6. 抽查至少 3 个构件的参数值。
7. 使用 Revit 撤销并确认参数和值恢复。
